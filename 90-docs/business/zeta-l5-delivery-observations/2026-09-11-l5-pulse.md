## 新規観測 (本 run で初めて state に記録)

- **Proof of Response (NEAR, arXiv:2502.10637)** — Illia Polosukhin & Alex Skidanov、preprint submitted 2025-02-15。
  仕組み: relay ノードの P2P ネットワーク (トポロジを NEAR スマコンに永続化、edge ごとに state channel)。リクエスタは (a) 宛先署名付き応答を宣言レイテンシ L_m 以内に受信、(b) 経路上の edge が切れたことの proof を受信、(c) どちらも来なければ L_m 超過分に比例した遅延料金を state channel で受領 — の 3 択を強制される。応答しないノードは反復リクエストで分離され、小 stake 側パーティションがペナルティ負担。
  位置づけ: bounded-latency 応答/可用性の検証可能 primitive。「データが served された」ことの証明を、宛先署名付き応答の受領 + edge 切断証明 + 遅延料金ストリーミングで経済的に強制する。PoR (NKN) が relay 量を証明するのに対し、PoR (NEAR) は応答性/可用性を証明・経済的に拘束 — L4 delivery 側の primitive。ただし本文中の「データが served された」スキームはサービスノード自身の署名応答に依存し、bandwidth/latency 宣言値自体の検証は上層プロトコルの責任と明記 (自己申告宣言値は信用しない構造)。
  出典: https://arxiv.org/abs/2502.10637 / https://www.near.ai/blog/announcing-proof-of-response / 実装状況: https://martian.engineering/work/near-por (Rust 実装、E2E テスト動作、testnet ファイル共有を準備中と記載 — 第三者ベンダー報告、未検証)。
  なお L5 の open problem (usefulness の証明) 自体は未解決のまま: PoR は「応答が来た/来なかった」の証明であり、有用配送の質は上層に委ねられている。

1. **RouterLink (WORLD3) — Proof of Latency Performance (PoLP) + Proof of Token Usage
   (PoTU)** — 分散 AI ルーティング網の検証コンポーネント。PoLP は応答時間、PoTU は
   token 消費量を検証対象とする。litepaper/blog、peer review 無し。
   https://blog.world3.ai/blog/introducing-routerlink-the-missing-network-for-open-ai-access
   (2026-01-08、backfill — 初回 run より前の日付、今回初出現)
   詳細セクション: https://docs.world3.ai/world3/routerlink-litepaper/10.-protocol-components

2. **The Usefulness Gap in Proof-of-Useful-Work: An Empirical Study of Pearl's cuPOW
   Protocol** (arXiv:2606.04819, cs.CR, 2026-06) — 実動 PoUW 初の系統的実測。
   検証は「計算の正しさ」を保証し「計算の有用性」は保証しない (ランダム行列 proof が
   検証を通ることを 44 pool-accepted shares で実証)。verifiability-usefulness 緊張の
   実数量化であり、L5 が delivery 領域で抱える核心問題 (relay 済み bytes ≠ 役に立った
   delivery) の計算領域における直接的な analog。
   https://arxiv.org/abs/2606.04819

3. **The Economics of Proof-of-Useful-Work** (arXiv:2606.06700, 2026-06) —
   PoUW の競争均衡モデル (Bitconia / Fortessia / Duplexia の 3 レジーム)。有用作業の
   報酬化が均衡でどう生き残るかの理論。L5 の useful-delivery インセンティブ設計への
   隣接理論。
   https://arxiv.org/abs/2606.06700

4. **verifyhash ProofParcel** (GitHub tool ドキュメント) — オフラインの B2B
   ファイル一式受け渡しレシート。納品ファイル集合 (relPath, content) を Merkle root に
   束縛し、署名 attestation + RFC-3161 timestamp を付与。明示的な trust posture:
   「署名はタイムスタンプではない」。自称 parcel メタデータは root から除外 (untrusted)。
   L5 の claim 境界 (レシート vs delivery vs timestamp) への隣接観察。
   https://github.com/verifyhash/verifyhash/blob/main/docs/PROOFPARCEL.md

5. **Filecoin FIPs Discussion #1009** (GitHub 設計議論) — PDP 設計スレッドが
   retrievability の「能力向上 (enablement)」と「保証 (guarantees)」を明示分離:
   「the new proof we aim to introduce can not provide retrievability guarantees.
   What we can provably ensure is efficient retrievability capabilities」。また
   「in the current stage we are not proposing protocol incentives for PDP」。
   Filecoin 設計議論の場でも L5 (retrieval/delivery 保証の証明) は未決着であることの再確認。
   https://github.com/filecoin-project/FIPs/discussions/1009

## L5 現在地 (観測のみ・判断はしない)

- L1 storage (Filecoin) → L2 availability (PDP) → L3 transmission (NKN PoR) →
  L4 delivery (AIOZ PoD) の設計・実装はいずれも現状維持。**L5 (useful delivery) を
  primitive として決着させた primary source は今回も観測されず** (unknown)
- 学界面の新しい観察: PoUW (useful *compute*) の「Usefulness Gap」実測 (2606.04819) が
  「検証可能な正しさ」と「経済的に有用な作業」の乖離を実データで定量化した。これは
  計算領域での L5 問題 (delivery done ≠ delivery useful) の同型事例。delivery 領域で
  同種の gap 実測 (例: relay 成功量と受信者価値の乖離) をした文献は今回の検索では
  見つからず (unknown)
- Filecoin 側では FIPs #1009 が「PDP は retrievability の保証ではなく能力向上の証明」

## 学界面: Proof of Bandwidth / Latency / Useful Delivery 主題の新規項目

1. **Signet: Scalable Network-Driven Proof of Notification** (ETH Zürich, ICDCS 2026)
   https://netsec.ethz.ch/publications/papers/Signet_ICDCS_2026.pdf
   path-aware network で traffic path 上の AS (Autonomous Systems) を packet 観測の中立 witness
   にする proof-of-notification。TESLA 対称鍵で wire speed 証明生成 (1.6 Mpps/core、per-packet
   ~0.6µs)。「第三者 witness をどこに置くか」問題への新アプローチ: インフラ (AS) 自体を witness
   にする。証明対象は notification の送達で、latency/performance は含まない
2. **A Survey of DePIN, Research Directions, and Open Challenges** (arXiv:2609.02125、
   IEEE Communications Surveys & Tutorials 掲載論文の preprint、2026-09 投稿)
   https://arxiv.org/html/2609.02125
   physical proof の検証遅延と reward finality の分離 (T_final ≥ T_p + T_w)、optimistic/ZK
   rollup による proof commitment 先行・後検証の体系化。PoB (Proof-of-Bandwidth) / PoR
   (Proof-of-Routes) 等の proof 分類表あり。delivery 証明の報酬即時性 vs 検証可能性の
   トレードオフを理論化
3. **A Repeated-Game Framework for Incentives in Decentralized Infrastructure Protocols**
   (arXiv:2608.12576、2026-08)
   https://arxiv.org/html/2608.12576
   DePIN 品質管理を繰り返し道徳的危険として定式化。"deterrence ratio" Γ (逸脱利得 ÷ 検出確率)。
   cryptographic attestation 型 (Filecoin storage proof 等) は detection gap が小さく stake で
   足りる一方、output sampling 型 (inference・bandwidth 作業の品質) は分離条件が最も厳しいと分析。
   Filecoin / Helium の実攻撃 (位置偽装・self-dealing) を例示
4. **CoinCeeper whitepaper: Proof-of-Network framework** (未出版 whitepaper — 信頼度低として記録)
   https://coinceeper.com/coinceeper-whitepaper.pdf
   統計的 bandwidth 検証 + 地理的希少性 + latency fingerprinting (beacon からの RTT による
   位置三角測量) を consensus weight 化する設計文書。EMA フィルタで非決定的な ping 間隔を
   決定的 state に変換。著者自身が「未出版、arXiv 投稿予定」と明記
5. **zkpbench** (GitHub 実装例 — 規模・出典の強度は低い)
   https://deepwiki.com/divij-mot/zkpbench
   RTT 測定を Noir/barretenberg の ZK 証明で privacy-preserving にし ERC-1155 badge として
   on-chain 検証する DePIN latency proof 実装。peer review 無し
6. **DAWN × Witness Chain Proof of Bandwidth 統合** (project blog、日付 unknown)
   https://claims-reward.github.io/dawn-airdrop/blog-posts/proof-of-bandwidth-validation.html 、
   https://docs.witnesschain.com/archive/proof-of-bandwidth
   watchtower 分散観測の Byzantine-resistant aggregation による decentralized speed test。
   DAWN 互換 router に PoB を常駐統合 (DPDK/VPP software router、multi-gigabit 目標)

既知・今回新規ではないもの (ベースライン確認): Proof of Backhaul (arXiv:2210.11546, 2022)、
Proof of Latency using VDF (Anttonen 修論 2022)、FairRelay (arXiv:2405.02973, 2024)。

## L5 現在地 (観測のみ・判断はしない)

- L1 storage → L2 availability (PDP) → L3 transmission (NKN PoR) → L4 delivery (AIOZ PoD) は
  いずれも設計・実装が現状維持。L5 (useful delivery) を primitive として決着させた primary
  source は今回も観測されず
- 学界面の重心の変化: (a) 証明の witness を AS/インフラに置く (Signet)、(b) 検証遅延と
  報酬 finality の分離を体系化 (DePIN survey)、(c) 品質作業型 proof の enforcement 困難性の
  理論化 (repeated game)。trustless な latency 証明の核心 (受信者時計の結託、地理性) を
  直接解いた paper は今回の検索では見つからず (unknown)

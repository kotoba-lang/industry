# ADR-2607122300: flagship maturity sprint — Indeed/kaonavi replacements to operable, discoverable businesses

**Status**: accepted
**Date**: 2026-07-12
**Deciders**: Jun Kawasaki (+ Claude, /loop 常設承認のうえ実行)

## Context

Following ADR-2607121700 (the isic-6399 meta-job-search venture), the
owner directed a standing loop: "実際に indeed 置き換え, kaonavi
置き換えの成熟度を向上, uiux も公開, business として成立するように
進めて". This ADR records what that sprint (12 iterations, 2026-07-12)
changed and the decisions that stick.

## Decisions and outcomes

### 1. Demo pages are build-time actor executions, not mockups

Both flagship demo pages (GitHub Pages) are generated by nbb scripts
that run the FULL OperationActor StateGraph — advisor → governor →
phase gate → approval interrupts — and render the post-run Store, the
real refusal verdicts and the append-only ledger those runs wrote.
This is the sticking architectural rule for fleet demo pages: **a
public page's compliance claims must be computed by the actor's own
`.cljc` at build time, never hand-typed.** In-browser interactivity is
scittle-run ClojureScript; every page has a headless nbb DOM-stub
harness plus real-browser (headless Chromium --dump-dom) verification.

### 2. Governed-op coverage extended where the law names the gap

- isic-6399 `:posting/correct` (repo ADR-0002): 職業安定法5条の4 の
  訂正義務. Same content gates as a fresh publication + a
  posting-not-live guard; corrections repeat with numbered records.
- isic-6310 `:assignment/propose`: kaonavi 配置転換 gap. HRBP-only
  RBAC, fairness gate refuses protected-attribute grounds, always
  human-approved, from/to+approver queryable (`:apply-assignment`).
- isic-6310 `talent.sim` fixed to pass `:phase 3` explicitly (the
  conservative default-phase change had silently broken its
  documented narrative).
- isic-6399 facts: 6 jurisdictions (added FRA: Code du travail
  L5331-1/L1132-1 + CPI L341-1 ff.; KOR: 채용절차법4조 +
  남녀고용평등법7조 + 저작권법91–98조), all with real consent
  sub-citations.

### 3. Operator path is real, and validated

`docs/operator-quickstart.md` per repo; isic-6399's generator takes an
operator `postings.edn` and builds THEIR governed board (holds with
real verdicts). The standalone layout (fresh shallow clones +
`npm install nbb`) was reproduced from scratch and works as
documented. Freshness automation: nightly GitHub Actions regeneration
in both isic-6399 (的確表示 as a scheduler) and the catalog repo,
commit-only-on-change, both runs verified green.

### 4. Public discovery surface

- Org landing: github.com/cloud-itonami (`.github` repo profile).
- Fleet catalog: <https://cloud-itonami.github.io/> — generated from
  kotoba-lang/industry's registry.edn (144 implemented / 646 entries,
  honest maturity breakdown), so the marketplace face cannot drift
  from the SSoT. Catalog repo ADR-0001 defers itonami.cloud cockpit
  integration: if that cockpit grows a marketplace surface it must
  CONSUME the same registry.
- Registry entries for 6310/6399 carry `:demo` URLs and op-coverage
  comments.

### 5. Upstream fixes shipped along the way (fleet-wide effect)

- kotoba-lang/langchain 9f4453d3: `langchain.db` unloadable under nbb
  (SCI fails on a quoted `$` inside an `or` expansion).
- kotoba-lang/langchain 0f966d06: `langchain.runnable`/`model`
  unloadable under nbb (cljs concrete map types in extend-protocol;
  nbb branch extends Keyword + :default with manual map/fn dispatch).
  These two are what made "run the actor at page build" possible.
- kotoba-lang/html f26595df: RAWTEXT refactor regression — `<script>`/
  `<style>` children of shape `[:hiccup/raw ...]` rendered as vector
  literals, breaking css/style-node and every generated page built
  against html main; fixed by unwrapping raw children in the RAWTEXT
  branch (breakout guard applies to the payload).
- kotoba-lang/industry: implemented-count test reconciled to 144 after
  a three-way promotion race (5820/6201/6202), attribution verified by
  diffing implemented-id sets against the 141-era commit.

All landed via server-side merges with west pins advanced by
single-entry API commits per `repos.edn :manifest-workflow`.

## Consequences

- Both replacements now have: full governed-op coverage with green
  suites (6399: 49 tests/225 assertions; 6310: 32/118), live verified
  demos, validated fork-to-production paths, concrete pricing/unit-
  economics/funnel docs, and a discoverable catalog → demo → fork
  funnel that actually exists end-to-end.
- Not done (known): real feed/search-index integrations and 6310
  real-data seeding remain operator-side; itonami.cloud marketplace
  surface awaits an owner-approved cockpit ADR; jurisdiction catalogs
  are 6 of ~194.

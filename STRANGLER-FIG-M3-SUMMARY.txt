(1) MULTI-WAY MERGE ALGORITHM ✓
================================================================================

Primary Function: merge-index-runs/2-5

Signature:
  (merge-index-runs runs index query-epoch)
  (merge-index-runs runs index query-epoch safe-epoch)
  (merge-index-runs runs index query-epoch safe-epoch key-range)

Features:
- Supports all 4 indexes: EAVT, AEVT, AVET, VAET (sparse references only)
- Canonical key ordering: newest epoch first via reverse epoch encoding
- MVCC multi-version concurrency control
- Tombstone filtering (retract operations suppress keys)
- Grouping by logical component identity
- Deterministic result ordering

Algorithm:
1. Filter runs by key range (optional)
2. Extract and filter rows by query epoch
3. Group by logical component identity
4. Select newest version per logical key
5. Filter out tombstones (retracts)
6. Sort by canonical physical key

Example Usage:
  (lsm/merge-index-runs [run1 run2 run3] :eavt 10)
  => vector of visible rows at epoch 10

================================================================================
(2) FILTERING LAYER ✓
================================================================================

Visibility Windows:
- visibility-window: Apply epoch-based filtering for tombstone suppression
- safe-epoch parameter: Controls retention of older versions
- MVCC snapshot isolation with pinned epochs

Range Filtering:
- key-range: Extract min/max key from runs
- range-overlaps?: Test range intersection for runs
- runs-in-key-range: Filter runs by key bounds, reduce I/O

Cache Prefix Filtering:
- query-filter-cache-hint: Generate cache filtering hints
- Returns {:cache-prefix :expected-runs}
- Guides host caching strategy for efficient prefetching

Example Usage:
  (lsm/visibility-window rows 10 5)
  => rows filtered by epoch visibility and safe-epoch boundary
  
  (lsm/runs-in-key-range runs {:min-key k1 :max-key k2})
  => only runs overlapping the key range

================================================================================
(3) RUN ORGANIZATION ✓
================================================================================

Level Boundaries:
- level-boundaries: Pre-compute level metadata from manifest
- Returns per-level stats: min-key, max-key, run-count, total-rows
- Used for run organization and query planning

Statistics Aggregation:
- run-statistics: Aggregate stats across index runs
- Returns: total-entries, total-bytes, level-distribution, key-range
- Guides query planning and compaction decisions

Query Planning:
- range-query-plan: Plan range queries with filtering and caching hints
- Returns: range-filter, relevant-levels, cache-hints
- Supports both point queries and range scans

Example Usage:
  (lsm/level-boundaries manifest-indexes)
  => {:eavt-l0 {:min-key "..." :max-key "..." :run-count 3 :total-rows 1000}}
  
  (lsm/run-statistics index-runs)
  => {:total-entries 5000 :total-bytes 50000 :level-distribution {...}}

# `kotoba`: ホモトピー型理論と仏教思想で紡ぐ、詩的計算言語

[![Rust](https://github.com/gftdcojp/hottgraph/actions/workflows/rust.yml/badge.svg)](https://github.com/gftdcojp/hottgraph/actions/workflows/rust.yml)

`kotoba`は、**ホモトピー型理論（HoTT）**を基盤とし、**仏教的生成思想（五蘊、般若心経）**および**有向多重グラフ構造**と調和する、詩的かつ形式的なプログラミング言語です。

「言葉（kotoba）によって、事（koto）が起こる場（ba）が生まれる」という思想を核とし、構文そのものが世界の構造と生成を語り出すことを目指します。

## 思想: 二層の世界観

`kotoba`は、世界の根源的な操作を担う**計算層 (Cubical Layer)**と、それによって豊かな構造が創発される**抽象層 (HoTT Layer)**の二層から成ります。

### 計算層 (Cubical Layer): 世界の根源的操作

| キーワード | 思想 | 形式意味論上の対応 | 説明 |
| :--- | :--- | :--- | :--- |
| `ku` | `空` | Interval `I` | すべての計算の基準となる一次元の「時間」を表す型。 |
| `zo` | `即` | Faces `i0`, `i1` | `ku`の両端。`i0`は「始点」、`i1`は「終点」。 |
| `ze` | `是` | Path `_≡_` | `a`と`b`の間の繋がり（等価性）を表す、`ku`上の関数。 |
| `en` | `縁` | Glue Type | 型と型を、`ze`（パス）に沿って「接着」する操作。 |

### 抽象層 (HoTT Layer): 構造の創発

## `Cubical Agda` への道: 4つのフェーズ

`kotoba` が目指すのは、`Cubical Agda` のように構成的で計算可能な能力を持つ、詩的な証明支援系です。その実現に向けたマイルストーンを、以下4つのフェーズに分けて定義します。

1.  **フェーズ1: 依存型の導入 (Dependent Types)**
    *   **目標**: 型の表現力を飛躍的に向上させ、証明の記述を可能にする。
    *   **実装**: `Π` (パイ) 型 (依存関数) と `Σ` (シグマ) 型 (依存ペア) をパーサー、コンパイラ、型チェッカーに導入する。
    *   **評価基準**: `Vector A n` のように、値 `n` に依存する型を定義・検証できること。

2.  **フェーズ2: 高次帰納型 (Higher Inductive Types - HITs)**
    *   **目標**: 円やトーラスといった、単なる点ではない「空間」そのものを型として定義する。
    *   **実装**: `gyo` (帰納型) の定義を拡張し、点のコンストラクタとパスのコンストラクタを同時に定義可能にする。
    *   **評価基準**: 円周 (`S¹`) を「点と、その点自身を結ぶループパス」から成る型として直接定義できること。

3.  **フェーズ3: 立方体計算規則 (Cubical Computation Rules)**
    *   **目標**: パス（等価性）に関する複雑な計算を自動化し、より高度な定理証明を可能にする。
    *   **実装**: `hcomp` (homogeneous composition) に代表される、立方体の面を「埋める」計算規則をコンパイラに実装する。
    *   **評価基準**: `hcomp` を用いて、関数外延性 (`(f: (x:A) -> B x) (g: (x:A) -> B x) -> (Π (x:A) -> f x ≡ g x) -> f ≡ g`) のような基本的な定理を内部で証明できること。

4.  **フェーズ4: Univalence の証明 (Proof of Univalence)**
    *   **目標**: `kotoba` の構成的な体系の上で、ホモトピー型理論の根幹を成す Univalence を定理として証明する。
    *   **実装**: これまでの機能を総動員し、`Univalence` (`(A:Type) (B:Type) -> (A ≃ B) ≃ (A ≡ B)`) の証明を記述し、検証エンジンに受理させる。
    *   **評価基準**: `Univalence` が `kotoba` の定理として検証されること。

## 検証エンジンとしてのコンパイラ設計

`kotoba`のコンパイラは、単なるトランスパイラではありません。型の整合性だけでなく、HoTTに基づいた**証明の正しさ**をも検証する「検証エンジン」として設計されています。コンパイルプロセスは以下の通りです。

1.  **構文解析 (Parser)**: `kotoba-parser`がソースをASTに変換。
2.  **検証・中間表現生成 (Verifier & VIR Generation)**: `kotoba-compiler`がASTを検証し、計算可能な**検証中間表現 (Verifiable IR)** に変換する。このステップで、型の整合性だけでなく、証明の正しさも検証される。
3.  **Rustコード生成 (Code Generation)**: `kotoba-compiler`がVIRから等価なRustコードを生成。
4.  **最終コンパイル**: `rustc`がネイティブバイナリを生成。

現在のコンパイラは、以下の高度な型チェック機能を備えています。
*   **コンテキストを意識した型検証**: `shiki x: T = ...` のような型注釈をヒントに、式の型が期待通りかを検証します。
*   **パターンマッチの網羅性**: `ou` 式の各分岐が同じ型を返すことを保証します。
*   **関数とパスの整合性**: `kan` 式が、`ze` (Path) や `en` (Glue) の文脈で、正しいシグネチャを持つか検証します。

## プロジェクト構造

本プロジェクトはCargoのワークスペースとして構成されています。

-   `kotoba-core`: `ku`, `ze`など、言語の核となる立方体データ構造の定義。
-   `kotoba-parser`: **再帰下降法**に基づいたLL(1)パーサー。ソースコードをAST（抽象構文木）に変換します。
-   `kotoba-compiler`: **検証エンジン**。ASTを意味解析し、最終的にRustコードを生成します。
-   `kotoba-cli`: コマンドラインインターフェース。

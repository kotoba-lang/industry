kotoba-lang EDA

半導体開発を web で完結するための設計。.kotoba/.cljc を EDA IR と workflow の正本にし、kami engine で schematic/layout/waveform を描画し、 murakumo inference と LLM を検証可能な proposal として統合する。

Architecture

Browser IDE

  • Project, source, canvas, verification, and copilot panes.
  • CLJS workspace for specs, RTL, SPICE, constraints, reports, and reviews.
  • SSE progress for synthesis, simulation, DRC, LVS, STA, and LLM jobs.

kotoba Store

  • Specs, netlists, layouts, reports, waivers, reviews, and releases as datoms.
  • GDS/OASIS, wave dumps, simulation databases, and large reports by CID.
  • Datalog views for provenance, sign-off state, and regression history.

kami Engine

  • WebGPU schematic graph and physical layout canvas.
  • Waveform, timing path, DRC/LVS overlay, and package/thermal views.
  • Stateless render arm; source of truth remains datom + CID.

murakumo + LLM

  • Scale-to-zero CPU/GPU jobs for inference and heavy EDA runs.
  • LLM agents produce review proposals, not sign-off decisions.
  • Financial, confidential, quality, and external-disclosure gates.

Flow

Spec · requirements, interfaces, clocks, resets, power domains, and test intent as EDN datoms.
Design · .kotoba/.cljc generators for RTL, PCell, constraints, and testbench code.
Verification · lint, simulation, formal, DRC, LVS, STA, and SPICE runs normalized to reports.
Review · LLM summaries and fix candidates captured as :eda.review/* proposals.
Release · sign-off bundle from immutable input/output CIDs, tool versions, reports, and waivers.

Safety Boundary

EDA reports are authoritative. LLM output is advisory and must become a review datom before it can be accepted. PDK licensing, customer NDA, export constraints, external model provider use, paid scale-up, waiver creation, and release candidate creation are policy-gated and auditable.
